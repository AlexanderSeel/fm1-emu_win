The first release of the whole emulator: the **instrument plugin** (AU, VST3, CLAP) as before,
and now also **fm1-live**, which plays a firmware in a window on your computer, for macOS and
Linux. The page, [joakimeriksson.github.io/fm1-emu](https://joakimeriksson.github.io/fm1-emu/),
needs no download and is always the latest.

## Downloads

| File | For |
|---|---|
| `fm1-plugin-0.2.0-macos-arm64.zip` | The plugin: Macs with Apple silicon, macOS 11 or later. Its `INSTALL.txt` says where each file goes. |
| `fm1-emu-0.2.0-macos-arm64.tar.gz` | fm1-live and fm1-emu, Macs with Apple silicon (with the JIT: the FM-1's real 240 MHz) |
| `fm1-emu-0.2.0-linux-arm64.tar.gz` | fm1-live and fm1-emu, 64-bit ARM Linux (with the JIT, new in this release) |
| `fm1-emu-0.2.0-linux-x86_64.tar.gz` | fm1-live and fm1-emu, x86-64 Linux (no JIT yet: interpreted, slower) |

Windows, and a JIT for x86-64, are planned for the next release.

**fm1-live** plays a firmware package: `./fm1-live --fwsc felucca.fwsc`. The packages: the
community firmwares on [the FM-1 Firmware Hub](https://thefirmwarehub.com/) (and the list on
the page, with each author's link), or M-VAVE's own `FM-1.fwsc`. The computer keyboard plays
the keys, and so does every MIDI input. Each archive's `README.txt` has the rest.

**Not signed:** macOS blocks the downloads until you allow them. For the plugin, after copying
it (as `INSTALL.txt` says):

```sh
xattr -dr com.apple.quarantine ~/Library/Audio/Plug-Ins/Components/FM-1.component ~/Library/Audio/Plug-Ins/VST3/FM-1.vst3 ~/Library/Audio/Plug-Ins/CLAP/FM-1.clap
```

and for fm1-live, in its folder: `xattr -d com.apple.quarantine fm1-live fm1-emu`.

## What's new since the plugin's 0.1.0

- **The plugin:** a CPU clock setting (240 MHz by default; 120 to 400), and firmware saves that
  move between the plugin and the page (export one, load it in the other).
- **The page:** it keeps your firmware and its flash between visits, with portable save backups;
  a new layout.
- **Sound fixes:** FM-106's and DUELL's sound was wrong under the JIT (a carry bug; now the same as
  the interpreter's), and
  four instruction decoding fixes found by checking the decoder against the vendor's own
  disassembler (a wrong pointer step in word loads and stores, which Felucca, DUELL, JIANT and
  others contain; a wrong register in a byte load from the stack; a pre- / post-increment mix-up;
  a crash).
- **Faster:** the Mac JIT chains code running from RAM, and the page's WebAssembly JIT compiles
  if/else blocks (X0X +46%).
- **For firmware authors:** `--flaky-core1 RATE` makes the second core misread memory now and
  then, as on some units, to test a firmware's fallback to one core.
